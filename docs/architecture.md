# Architecture

One API and one worker share a SQLite WAL database and a persistent filesystem. Public routes check completed processing, complete provenance and visibility independently of identity labels. A duplicate group is a presentation unit; source filters are evaluated on one post row and all-person matching on one member image. Sources share post records so a caption update applies to every media item in a post.

Person saves use BEGIN IMMEDIATE, unique trimmed group names and one transaction for creation, membership and accounts. Reference changes increment a monotonic library version and update or insert a single active rematch task per image. Workers cache embeddings, select only unknown faces and use revision predicates when writing back. A reference update during processing reuses the running task if unknown faces remain. Human choices are independently locked and undo uses an optimistic revision check.

SHA-256 identifies exact files. pHash retrieves candidates; aspect ratio and SSIM confirm variants. Every cross-group pair must pass before automatic merge. Explicit separation decisions persist across subsequent imports. The highest-resolution eligible member represents the group; original bytes are retained separately from orientation-normalized display copies.

Session tokens are random, hashed in storage, time-limited and sent in HttpOnly SameSite=Strict cookies. Mutations require a same-origin custom header. Reference files and cookies have no public static mount. The public media endpoint repeats visibility and provenance checks. Import paths are resolved under the configured mount; supported download hosts are allowlisted.

Dependencies use current stable releases pinned in lockfiles. The frontend uses pnpm 12.21.0, pinned via packageManager; local and Docker installs use pnpm-lock.yaml with --frozen-lockfile. TypeScript remains at 5.9.3 because the current openapi-typescript release requires TypeScript ^5.x. SCRFD-10G-KPS and R50@WebFace600K FP32 weights are pinned to buffalo_l commit d09715916a0778919a770c343533641e250b8699 and SHA-256 hashes. ONNX Runtime CPU sessions are lazily initialized under a process lock and shared across calls; tensors and detector sizes are call-local. Embeddings are versioned, finite, nonzero 512-dimensional float32 vectors. Staged reference uploads carry the model version. Old features are not migrated.

Schema version 2 adds posts.author_name through an idempotent startup migration. Account usernames remain the stable matching keys; display names use linked people before imported nicknames. Publisher filters accept person:<id> to resolve all currently linked platform accounts in SQL while keeping date predicates on the same post. Legacy platform:username filters remain supported.

Schema version 3 preserves the selected box for uploaded reference images. Reference crops and management avatars remain admin-only; library references use their face box. Legacy uploaded references recover their box lazily by matching the saved embedding against detected faces, cache the recovered box, and refuse to show the full image when recovery fails.

Schema version 4 adds a durable file-cleanup queue. Image deletion removes dependent records in one transaction, preserving shared posts and unselected duplicate members. Running image jobs or imports block deletion. Managed imports write assets under the database write transaction; cleanup rechecks image ownership before removing files and retries failed removals on startup or worker idle. External import/download source directories are untouched.

The worker invokes gallery-dl through app.downloader using its own Python interpreter. The wrapper maps X details.full_text into the existing tweet text fields before gallery-dl transformation, preserving existing legacy text and note_tweet priority. Importing metadata uses nonempty caption fallbacks; X image alt text is not treated as the post caption.

Schema version 5 adds image feedback, a private HMAC key and independent submission timestamps. Feedback belongs to an image and cascades on image deletion; public group reads include only currently visible eligible members. Pending feedback is an additional review reason, independent of face and provenance work. Moderation preserves resolved content unless explicitly deleted.

Feedback submission checks rolling 60-second and 24-hour quotas inside the same BEGIN IMMEDIATE transaction as the insert. Only successful submissions consume quota; moderation/deletion cannot reset it. HMAC IP keys and timestamps expire after 24 hours (cleanup on startup and subsequent accepted submissions). Uvicorn's trusted proxy handling supplies the client address; application code never reads forwarding headers directly. No limiter key or address is returned by the API.

Download policy is enforced at task submission, worker execution, extractor dispatch and before media metadata is yielded. X authors require explicit protected=false; Instagram owners are looked up by ID with no persistent profile cache and require is_private=false. Restricted/unknown states fail closed. Each attempt uses a disposable directory and validated 0600 cookie snapshot; only completed extraction is imported. Request transport confines HTTPS destinations to platform/CDN domains and pins connections to validated public DNS results, retaining TLS hostname verification and stripping session headers for CDN requests.

RequestGuard bounds admission, request-body buffering and per-client state before parsing, including unauthenticated admin uploads. It operates on the trusted ASGI client address and assumes one API process. Public database connections use a progress-handler deadline and reduced lock wait; feedback quotas remain transactional and persistent. Limits are configured only by deployment environment.

The single worker holds its existing OS lock and dispatches into a bounded compute pool plus one import/download executor. Transactional claims only occur with a free executor slot and exclude earlier active tasks for the same image as well as any running task for that image. Detection mode is persisted in payload: imports use auto; manual redetection upgrades queued auto tasks or appends one deduplicated highres task after running auto work. Retries retain payload. Shutdown stops claims and drains executors; startup requeues interrupted tasks, or marks cancellation requests cancelled.

Auto detection runs 640, then reruns from the original at 1280 only when post-filter/NMS results are empty or any effective short side is below 48 pixels. Highres runs 1280 directly. The final result replaces the first pass, including empty results and inference errors; recognition runs only on final boxes. Cancellation is checked between passes, before each feature, and inside the write transaction. Existing human decisions and revision/reference-version checks remain in force.
